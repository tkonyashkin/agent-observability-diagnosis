# Eval-сет сервиса диагностики

Версия 1.2, заморожена 28.10.2026 (КТ-2): 80 кейсов. Проверяет наш сервис, а не агента: по трейсу сбойного запроса сервис должен найти шаг агента, на котором возник сбой, определить вид сбоя и поставить правильный статус.

## Один кейс: одна строка

Каждый кейс сводит в одну запись цепочку **запрос агенту → внесённая поломка → жалоба инженера → эталонный вид, шаг и статус**.

| Поле | Что содержит | Кто видит |
|---|---|---|
| `agent_case` | Ссылка на кейс Junkie (`junkie_id`, группа, фикстура, пользователь) и запрос агенту | сервис получает трейс этого запроса |
| `agent_reference` | Эталон агента из Junkie: `action`, `relevant_doc_ids`, `filters`, `order_by`, `has_more` | только оценщик |
| `injection` | Поломка: шаг и механизм. `null` в кейсах без сбоя, список в составных | только оценщик |
| `trace_variant` | Что доступно сервису: `git_sha`, входы и выходы генераций, вход и выход инструмента, доступ к источнику, снимок индекса | задаётся харнессом |
| `complaint` | Комментарий инженера к заявке, как он придёт в сервис | сервис |
| `observations` | Что будет видно в трейсе и источнике по каждому шагу. На КТ-3 сверяем с реальным трейсом | только оценщик и разметчики |
| `expected` | Вид сбоя, корневой шаг, вторые причины, статус, вердикт по каждому шагу, эталонный вид корневого шага, обязательные ссылки на доказательства | только оценщик |
| `symptom_group` | Группа кейсов с одинаковым симптомом и разными причинами | оценщик |

Шаги, виды и статусы описаны в [taxonomy.md](taxonomy.md).

| **Итого** | **54** | **26** | |

**Почему такой размер.** Всего 80 кейсов, holdout составляет около трети. На 49 оцениваемых кейсах dev одна ошибка меняет точность примерно на 2 п. п. Для точности 80 % доверительный интервал 95 % составляет примерно ±11 п. п. Этого хватает, чтобы отличить сервис от правил (ожидаем у правил не выше 50 % по «вид + шаг»: они не различают промпт и модель без эталона). По 11 кейсов на вид дают по 5–6 на каждый из двух шагов вида, этого хватает для среза по шагам. Из 26 кейсов holdout берутся 20 для замера north-star. Полный прогон dev стоит около 50 долларов при трёх повторах (раздел 3.3 design doc). Внесение и проверка каждой поломки требуют ручной работы.

## Откуда кейсы и чем они отличаются от примеров разработки

- **Запросы и эталон агента**: из [eval-сета Junkie](../agent_eval/SOURCE.md). Мы не придумываем запросы под свой сервис: набор собран другой командой для другой задачи и размечен до нашего проекта.
- **Поломки**: наши, по построению. В тестовом запуске меняем выход или настройки конкретного шага. Один механизм можно повторить на разных запросах без отдельного коммита. `git_sha` указывает на версию кода агента, а настройки поломки остаются у оценщика. Сервис видит код без истории и сообщений коммитов.
- **Жалобы** пишет участник, который видит только итоговый ответ агента, а не поломку.
- **Примеры для разработки** промпта диагноста строятся на кейсах Junkie из резерва (`E03`, `E24`, `E45`, `E97`), которых нет в eval.
- **Holdout** отличается от dev сильнее, чем перефразом: другие группы кейсов Junkie (пересечение по `group_id` запрещено и проверяется), другие механизмы поломок (несовпадение версий эмбеддингов, искажённая кодировка, кэш адаптера, нестабильный сбой при высокой температуре).

## Ground truth

1. **По построению:** вид сбоя, корневой шаг и эталонный вид шага задаёт поломка.
2. **Проверка поломки на КТ-3:** агент без поломки проходит кейс Junkie минимум в 4 из 5 прогонов. С поломкой корневой шаг неверен минимум в 4 из 5 и итог неверен. Если условие не выполнено, кейс исключается из прогона до запуска сервиса. Исключённые кейсы и причины перечисляются в результатах.
3. **Вердикты шагов** считаются автоматически: выход каждого шага сравнивается с эталонным видом из [taxonomy.md](taxonomy.md) по прогону без поломки.
4. **Статус и спорные шаги** размечаются двумя людьми на подвыборке, см. [annotation/README.md](annotation/README.md).

## Разбиение и заморозка

- `dev.jsonl`: 54 кейса, на них отлаживаем сервис.
- `holdout/holdout.jsonl`: 26 кейсов. До КТ-4 файл хранится у команды вне Git. В репозитории открыт только [manifest.json](holdout/manifest.json) с составом, группами Junkie и хешем.
- Версия 1.2 после заморозки не меняется. Новые кейсы можно добавить в следующую версию, не подменяя ими результаты на версии 1.2.

## Проверка

```bash
python3 kt2/service_eval/scripts/validate.py
```

Скрипт проверяет схему, состав классов, совпадение запросов и эталонов с Junkie, согласованность вида и шага. Для holdout он проверяет только открытый манифест. Содержимое и хеш проверяются только при явном запуске с `--holdout ПУТЬ` после открытия набора на КТ-4.
