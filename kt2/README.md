# КТ-2: методика оценивания

Сервис диагностики сбоев агента проверяется на двух наборах.

| | Eval-сет агента | Eval-сет сервиса |
|---|---|---|
| Что проверяет | Правильно ли агент Junkie отвечает на запрос | Правильно ли наш сервис находит шаг и причину сбоя агента |
| Единица | Запрос пользователя к агенту и эталонный ответ | Запрос агенту → поломка → жалоба инженера → эталонный шаг, вид и статус |
| Откуда | Соседняя команда, [Junkie](https://github.com/qrvmil/junkie/tree/8f890da7a2e0f978eaf2ae74bf4b448334a420fb) | Мы, поверх кейсов Junkie |
| Размер | 140 поисковых кейсов и 10 кейсов добавления | 54 dev и 26 holdout, всего 80 |
| Где | [agent_eval/](agent_eval/SOURCE.md) | [service_eval/](service_eval/README.md) |
| Роль у нас | Источник запросов и эталонного вида шагов. Проверяет работу агента без поломки. После MVP используем как контрольный набор для автопатча | Метрики раздела 3.1 и 5.2 design doc |

## Почему Junkie

Для MVP нужен конкретный агент с трейсами, контрактом инструментов и размеченным набором. У Junkie описаны шаги разбора и поиска, [контракт инструментов](agent_eval/fixtures/tool_contract.json) с обязательными полями трейса, 140 кейсов с эталонными шагами (`gold_steps`, `expected_calls`) и фиксированным окружением. По этим данным мы проверяем итог агента и каждый шаг.

Код агента Junkie запланирован у них на КТ-3. Поэтому на КТ-3 мы пишем минимального агента по их контракту (`junkie-ref`) с трейсингом в Langfuse и вносим поломки в него. Если их код будет готов раньше, подключаем его через те же настройки проекта.

    ├── annotation/
    │   ├── README.md             процедура двойной разметки
    │   ├── blind_cards.jsonl     20 карточек без ответов для двух разметчиков

## Что осталось сделать перед сдачей

1. Два участника независимо размечают [карточки](service_eval/annotation/cards.md) по [инструкции](service_eval/annotation/README.md). После расчёта согласия вписываем результат в раздел 5.1 design doc.
2. Один участник хранит `holdout.jsonl` вне Git до КТ-4 и не участвует как решающий инженер в замере north-star. В репозитории остаётся манифест с хешем файла.
3. `python3 kt2/service_eval/scripts/validate.py` проходит без ошибок.
